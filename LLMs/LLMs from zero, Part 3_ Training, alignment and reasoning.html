Module 5Training

5.1 The three stages of building a chatbot

1. PretrainingNext-token prediction on trillions of tokens of internet text. Result: knows a lot, but just continues text.
→
2. Supervised fine-tuningThousands of good question → answer examples. Result: follows instructions.
→
3. Preference tuningRLHF or DPO using human (or AI) preferences. Result: helpful, honest, safer.

A common analogy: pretraining is reading the whole library; SFT is learning the format of answering questions; preference tuning is learning which answers people actually like. Stage 1 uses over 95% of the compute.

Prompt: "What's the capital of France?"

After pretraining only: "What's the capital of Germany? What's the capital of Italy? …" (it continues the pattern of a quiz page)

After SFT: "The capital of France is Paris."

5.2 Pretraining and the loss function

The model reads text and, at every position, predicts the next token. The loss is cross-entropy: the negative log of the probability the model gave to the correct token.

loss = − log p(correct next token)

If the model was confident and right, the loss is near 0. If it gave the right answer a tiny probability, the loss is large. Drag to see:

p(correct)0.50
0.69loss

The curve shoots up as p approaches 0: being confidently wrong is punished hard.

Data: web crawls (like Common Crawl), code, books, papers, and more; heavily filtered for quality, deduplicated, and cleaned of personal data. Modern models train on 10–40 trillion tokens.

Compute rule of thumbTraining FLOPs ≈ 6 × N × D, where N = parameters and D = training tokens. (About 2ND for the forward pass and 4ND for the backward pass.)

5.3 Scaling laws

Researchers found that loss falls smoothly and predictably (as a power law) when you increase model size, data, or compute. This lets labs predict how a huge model will perform by training small ones first.

The big question: with a fixed compute budget, should you build a bigger model or train on more data? The Chinchilla paper (2022) answered: grow both equally. The compute-optimal ratio is roughly 20 training tokens per parameter. Chinchilla (70B parameters, 1.4T tokens) beat the much bigger Gopher (280B), which was undertrained.

"Then why was Llama 3 8B trained on 15 trillion tokens (almost 2,000 per parameter)?" Chinchilla optimizes training cost only. But a model is trained once and used millions of times. A smaller model trained far longer is cheaper to run, so labs now "over-train" small models on purpose.

5.5 FlashAttention

A GPU has two kinds of memory: big but slow HBM (the 80 GB), and tiny but very fast SRAM on the chip. Standard attention writes the full n × n score matrix to slow HBM and reads it back several times. For long sequences, moving data takes longer than the math.

FlashAttention splits Q, K, V into tiles that fit in SRAM, computes attention for each tile there, and combines the results with a clever running softmax. The full n × n matrix never exists in HBM.

Key factsIt's exact, not an approximation: same output as normal attention. It's 2–4× faster, and memory grows linearly with n instead of quadratically. The compute is still O(n²). It's an "IO-aware" algorithm: it wins by reducing memory traffic, not math.

5.6 Quantization

Quantization stores weights with fewer bits, so the model takes less memory and runs faster. A 70B model needs 140 GB in FP16 but only about 35 GB in 4-bit.

scale = max|w| / (2^(bits−1) − 1)    q = round(w / scale)    w ≈ q × scale

Below, 8 weights are squeezed into fewer bits. Lower the bits and watch the error grow. Then add an outlier.

Bits4
0average error
0scale

One big outlier stretches the scale, so all the small weights get rounded to 0. Real LLMs do have outlier values, which is why methods like LLM.int8(), GPTQ, and AWQ handle them specially.

TermMeaning
PTQ (post-training quantization)Quantize an already-trained model. Fast and common (GPTQ, AWQ).
QAT (quantization-aware training)Simulate quantization during training so the model learns to cope. Better quality, more expensive.

5.7 Supervised fine-tuning (SFT)

SFT continues training on examples of good conversations: an instruction and an ideal response. It's still next-token prediction, with one twist: the loss is only counted on the response tokens, not the prompt. We want the model to learn to answer, not to write questions.

Faded = prompt tokens (no loss). Green = response tokens (loss counted). The special tags are the model's chat template.

Quality beats quantity: a few thousand very good examples can work better than a million mediocre ones.

5.8 LoRA and QLoRA: fine-tuning on a budget

Full fine-tuning updates every weight, so you need the full 16 bytes per parameter. LoRA (Low-Rank Adaptation) freezes the original weights and learns a small "patch" instead.

W' = W + B·A    (W frozen, d × k;  B is d × r,  A is r × k,  r is small)
Matrix size d (= k)4096
Rank r8

Why does a tiny patch work? Researchers found that the change needed to adapt a model to a task has low "intrinsic rank": it can be described by far fewer numbers than the full matrix.

LoRA detailWhy it matters
B starts at zero, A randomSo B·A = 0 at the start, and training begins exactly from the original model
Scaled by α / rA knob controlling how strongly the patch affects the output
Usually applied to attention matrices (Q, K, V, O), often FFN tooThat's where adaptation helps most
Can be merged after training: W' = W + BANo extra inference latency
Adapters are tiny files (MBs)Keep one base model and swap adapters per task or per customer
QLoRALoad the frozen base model in 4-bit (a format called NF4), keep the LoRA adapters in BF16, and train only the adapters. This made it possible to fine-tune a 65B model on a single 48 GB GPU. Extra tricks: double quantization and paged optimizers.

Which approach should you pick?

ApproachCostUse when
PromptingNoneTry this first; the task is general
RAG (Part 4)LowThe model needs facts that change or are private
LoRA / QLoRAMediumYou need a new style, format, or skill and have good examples

Trap: "Fine-tuning is the best way to add new knowledge." Usually not. Fine-tuning is good at teaching behavior and format; it's unreliable for adding facts and can increase hallucination. For knowledge, use RAG. Also watch out for catastrophic forgetting: heavy fine-tuning can erase general skills (LoRA reduces this risk).

Module 6Alignment and reasoning

6.1 Why SFT isn't enough

SFT teaches the model to imitate example answers. But writing perfect answers is slow and expensive, and there are many good answers to each question. It's much easier for a person to compare two answers and say which is better. Preference tuning uses those comparisons.

Prompt: "My code throws IndexError. Help?"

Response A: Asks to see the code, explains the common causes (off-by-one in loops, empty lists), and shows how to check the index range. chosen
Response B: "IndexError means the index is out of range." rejected

One preference pair. Datasets have tens to hundreds of thousands of these.

A famous result from InstructGPT (2022): people preferred answers from a 1.3B model trained with RLHF over answers from the 175B GPT-3 base model.

6.2 Step 1 of RLHF: train a reward model

The reward model reads a prompt and a response and outputs one number: how good is it? It's trained so that the chosen answer gets a higher score than the rejected one, using the Bradley–Terry formula:

P(A beats B) = σ(r_A − r_B)    loss = − log σ(r_chosen − r_rejected)

σ is the sigmoid function: it squashes any number into 0 to 1.

r_chosen − r_rejected1.00
73%P(chosen is better)
0.31loss

When the reward model scores the chosen answer well above the rejected one, the loss is small. If it ranks them backwards, the loss is large and training corrects it.

The KL penalty measures how far the model has drifted from the SFT model it started from. Why is it needed? The reward model is only an imperfect copy of human judgment. If the LLM is free to optimize against it, it finds loopholes: very long answers, flattery, repeating phrases the reward model likes. That's called reward hacking. The KL term keeps the model close to sensible behavior.

β (KL weight)Result
Too smallModel drifts far and reward-hacks: high reward score, worse real answers
Too largeModel barely changes from the SFT model

PPO (Proximal Policy Optimization) is the RL algorithm. Its main trick is clipping: each update is limited so the model can't change too much in one step, which keeps training stable. The downside is complexity: RLHF with PPO juggles four models at once.

6.4 DPO: preference tuning without RL

Direct Preference Optimization (2023) showed you can skip the reward model and the RL loop. The math shows that the optimal RLHF policy has a closed form, so you can train the LLM directly on preference pairs with a simple classification-style loss:

loss = − log σ( β [ log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l) ] )

In plain words: increase the probability of the chosen answer (y_w) and decrease the probability of the rejected one (y_l), measured relative to the frozen reference model so it doesn't drift too far.

6.5 Reasoning models

Models like OpenAI's o1 and DeepSeek-R1 are trained to "think" before answering: they write a long chain of thought, try approaches, check their work, and backtrack. This opened a new way to improve performance: test-time compute. Letting the model think longer at answer time improves accuracy on hard problems, in addition to making the model bigger.

How are they trained? With RL on problems that have verifiable answers: math with a known result, code with unit tests. No human judge or learned reward model is needed; a simple program checks if the final answer is right. This is called RL with verifiable rewards.

DeepSeek-R1 milestoneWhat it showed
R1-ZeroPure RL on a base model, no SFT. Long reasoning and self-correction ("aha moments") emerged on their own, but output was messy and mixed languages.
R1A small "cold start" SFT set first, then RL, then more SFT and RL. Readable and strong.
Distilled modelsFine-tuning small models (e.g., 7B) on R1's reasoning traces made them much better reasoners. Distillation beat running RL on the small model directly.

6.6 GRPO: the RL algorithm behind R1

Group Relative Policy Optimization drops PPO's value model. For each prompt, it samples a group of answers, scores them, and judges each answer against the group's average:

advantage_i = (reward_i − mean(group)) / std(group)

Answers better than the group average get pushed up; worse ones get pushed down. A KL penalty to the reference model is still used.

Prompt: "What is 17 × 24?"  (correct answer: 408)

–group mean reward
–std

Reward = 1 if the final answer is 408, else 0. Notice: if all 6 answers are right (or all wrong), every advantage is 0 and nothing is learned from that prompt. Useful prompts are ones the model sometimes gets right.

"Why GRPO over PPO?" No value model, so it uses less memory and is simpler. The group average acts as the baseline. It fits naturally with verifiable rewards, where you can cheaply score many samples per prompt.

ReviseInterview answers

What are the stages of training a chat LLM?Pretraining (next-token prediction on huge unlabeled text), supervised fine-tuning (instruction–response pairs), and preference tuning (RLHF or DPO). Reasoning models add RL with verifiable rewards.
What are scaling laws and what did Chinchilla show?Loss falls as a power law in model size, data, and compute. Chinchilla showed that for a fixed compute budget, parameters and tokens should grow together, about 20 tokens per parameter; many earlier models were undertrained.
How much memory does training a 7B model take?About 16 bytes per parameter with Adam and mixed precision (weights, gradients, FP32 master weights, two Adam states): about 112 GB plus activations.
What is FlashAttention?An exact, IO-aware attention algorithm that processes tiles in fast on-chip SRAM and never writes the n × n matrix to HBM. Faster, and memory linear in sequence length.
Explain quantization and its trade-off.Storing weights in fewer bits (INT8, INT4) to cut memory and speed up inference, at some accuracy cost. Outliers are the main difficulty. PTQ quantizes after training; QAT trains with quantization simulated.
How does LoRA work?Freeze W and learn a low-rank update BA with small rank r. Far fewer trainable parameters, B starts at zero so training starts from the original model, and the update can be merged for zero extra latency.
What is QLoRA?LoRA on top of a base model quantized to 4-bit NF4. Makes fine-tuning large models possible on a single GPU.
Explain RLHF.Collect human comparisons, train a reward model with a Bradley–Terry loss, then optimize the LLM with PPO to maximize reward minus a KL penalty that keeps it close to the SFT model.
Why the KL penalty?To prevent reward hacking and keep outputs fluent; the reward model is imperfect and the policy would exploit it.
DPO vs RLHF?DPO skips the reward model and RL loop, training directly on preference pairs with a classification-style loss relative to a reference model. Simpler and more stable; PPO-based RLHF is online and more complex.
What is GRPO?A PPO variant without a value model. It samples a group of responses per prompt and uses each response's reward relative to the group mean (normalized by std) as its advantage. Used for DeepSeek-R1.
What is test-time compute?Spending more computation at inference, e.g., longer chains of thought or multiple samples, to get better answers. Reasoning models are trained to use it well.
